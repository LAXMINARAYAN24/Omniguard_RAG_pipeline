\textbf{Note on scope.} This is a simulated retrieval environment: real
TF-IDF embeddings and real generated text throughout, but
\texttt{doc.answer} is a ground-truth label standing in for what a live
LLM would extract from a retrieved passage, for every ring and every
baseline alike. No live LLM sits in the evaluation loop. This limitation
is stated here and repeated in \Cref{sec:limitations} rather than left
implicit.

\subsection{Debugging and Verification Log}
\label{sec:debugging}

This project's development produced eight distinct, measured software
bugs, each caught by direct measurement rather than by inspection alone
and each fixed with a specific, verifiable change. \Cref{tab:debugging}
lists them in the order they were found. This log is presented as part of
the project's methodology, on the view that a defense evaluation's
credibility rests as much on how its own measurement errors were caught
as on its final numbers.

Bug \#7 deserves a fuller note here beyond the table, since it concerns
this project's own headline novel mechanism and was found and fixed after
an earlier version of this report had already stated the opposite
conclusion. The original claim --- that GWCC ``resolves cases the fast
path alone would not'' --- has two separable parts. The first, that
Ring~3 is invoked specifically because the contention signal fires on
cases cohesion alone would wave through, was and remains true, verified
directly. The second, that GWCC's own aggregation step, once invoked,
recovers a different and correct answer that a plain vote on the same
input would have missed, was asserted but had not actually been tested.
Testing it directly is precisely what surfaced bug \#7: the aggregation
step, as originally implemented, provably never did this, in any of the
653 escalated cases checked. \Cref{sec:results} and \Cref{sec:discussion}
report the fixed mechanism's own real, measured, non-zero ceiling, rather
than repeating the original, disproven claim.

One further non-bug finding is worth recording alongside
\Cref{tab:debugging}: ShieldRAG's push--pull query-time embedding
reshaping, as translated into this evaluation's baseline
implementation, is mathematically a no-op in this environment --- it
reinforces whichever answer already holds the retrieval plurality and
cannot flip the outcome, confirmed empirically as zero divergent
outcomes against Vanilla RAG across every attacked case tested. This is
not a bug in the sense of an incorrect implementation; it is a genuine,
measured property of this specific translation of the cited algorithm
into a TF-IDF, ground-truth-label evaluation setting, reported here for
the same reason every other measured limitation in this project is
reported rather than smoothed over.

\subsection{Evaluation Methodology in Practice}
\label{sec:eval-practice}

\textbf{Corpus.} Sixteen real topics (photosynthesis, the TCP three-way
handshake, the causes of the French Revolution, machine-learning
overfitting, and twelve others), each with genuine associated keywords, a
genuine correct answer, and one or more genuine incorrect answers.
Clean and attack text alike are drawn from one shared generator with five
distinct sentence templates (\Cref{sec:shared-generator}), scaled to 30
documents per topic for the reported evaluation: 480 reference documents,
217 TF-IDF dimensions.

\textbf{Attack regimes (six).} Clean, standard, PIDP, collusion (minor
and major poison counts, reported together), stealth collusion, and
silent --- described in full in \Cref{sec:attack-simulator}.

\textbf{Systems compared (six).} Vanilla RAG, DRS Only, ShieldRAG Only,
RAGuard/ZKIP, TriShield, and OmniGuard-RAG (\Cref{sec:results}).

\textbf{Evaluation modes.} A main comparison (all six systems against all
six attack regimes) and a per-ring ablation ladder (Ring~0 alone,
$+$Ring~1, $+$Ring~2 cohesion-only, $+$Ring~2 both signals), the latter
deliberately excluding the Dynamic Trust Store at every step so that its
cross-query effect cannot mask what a single ring does or does not
contribute in isolation (\Cref{sec:ablation-results}).

\textbf{Statistical rigor.} Eight independently regenerated seeds ---
$7, 11, 23, 41, 59, 79, 97, 113$ --- 200 queries each, 1{,}600 queries per
system in total, with every metric reported as a mean and a Student's-$t$
95\% confidence-interval half-width (\Cref{sec:multiseed}), alongside a
real, separately measured wall-clock orchestration latency next to the
call-count estimate every system reports (\Cref{sec:compute-cost}).
